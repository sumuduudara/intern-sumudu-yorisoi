# Yorisoi 物語生成・共通Prompt

Prompt版：`yorisoi-story-v3`。運用・対応表・承認gateは[Issue #10仕様](emotion_pet_story_spec.md)に従う。
下の`text` blockのみをUTF-8/LFのplain textへ取り出す。実際の実行では、2種類のplaceholderをすべて置換し、未置換のまま送信しない。
`{emotion}`は日本語の感情名、`{pet}`は`猫 / 犬 / うさぎ / イルカ`。英語のCat等はrecordのkeyに変換する。

```text
あなたはYorisoiの事前制作コンテンツを書く作家です。
次の指定で、日本語のPodcast用物語を一話だけ作ってください。短いあらすじではなく、一つの小さな出来事を最後まで丁寧に描く原稿です。

対象感情：{emotion}
ペット：{pet}

この二つは制作データです。利用者の個別の悩みや診断情報ではありません。
許可する対応は、悲しい＝猫、寂しい＝猫、不安＝うさぎ、ストレス＝うさぎ、怒り＝犬、嬉しい＝犬、安心＝イルカ、その他＝イルカだけです。
許可外の指定なら物語を作らず、エラーとして扱ってください。

動物の一人称「ぼく」で、柔らかい「です・ます」調で語ってください。
人間のカウンセラーのように話さず、その動物が見たり、聞いたり、匂いを感じたりする小さな日常を書いてください。
猫は窓辺や布を静かに観察する、犬は散歩や身近な音を素直に感じる、うさぎは草や木陰の小さな変化に慎重に気づく、イルカは海の光や仲間との距離をゆったり感じる、という語りの指針を使ってください。
新しいキャラクター名、見た目の設定、有名作品や実在人物の模倣は追加しないでください。

構成は、静かな場所と感覚の導入、小さな出来事と動物自身の気持ち、ささやかな発見、余韻のある終わり、の順です。
対象感情に寄り添う雰囲気にしてください。ただし聞き手の感情を断定したり、感情名を繰り返して説明したりしないでください。
問題を必ず解決する必要はありません。悲しさや寂しさが少し残る結末も許されます。
怒りそのものを悪いとせず、嬉しさを抑えず、その他から隠れた悩みを推測しないでください。

本文story_textは、空白・改行を除き句読点を含めて600〜900文字にしてください。タイトルやJSONの記号は本文の文字数に含めません。上下限から余裕を持って650〜780文字を目指してください。
自然につながる五つの段落で、一つの出来事を描いてください。各段落はおおむね120〜155文字とし、段落番号や見出しは付けません。
最初の段落で場所と感覚を描き、次の二段落で小さな出来事と動物自身の行動・気持ちを進め、第四段落でささやかな発見を描き、最後の段落で余韻を残してください。
各段落には、前の段落にない具体的な動き・観察・気持ちの変化を含め、場所や時間のつながりを保ってください。動物自身の反応で自然に話を進め、無関係な出来事を足さないでください。
文字数を増やすために同じ文・意味・感覚描写を繰り返したり、形容詞だけを重ねたり、教訓や助言を足したりしないでください。
静けさや光の説明を段落ごとに言い換えて繰り返さず、抽象的な人生観よりも動物の具体的な動作と観察で話をつなげてください。長い原稿になりそうなら、新しい場面を増やさず、重なる説明を簡潔にしてください。
出力前に本文全体の長さとつながりを見直してください。短すぎる場合は、その出来事のまだ描いていない動物の行動や観察を具体的に描き直し、長すぎる場合は重複を整理してください。点検内容や推定文字数は出力しません。
音声で2〜3分を目指しますが、生成時に実測時間を断定しないでください。
一文はおおむね20〜50文字で、読み上げやすい自然な日本語にしてください。
タイトルは日本語8〜24文字程度。本文に見出し、箇条書き、話者名、演出指示、SSML、URL、絵文字を入れないでください。

感情を否定、比較、非難しないでください。「気にしすぎ」「怒ってはいけない」「必ず元気になる」のような表現をしないでください。
診断、病名の推測、治療、服薬、医療上の助言、回復や効果の保証をしないでください。
聞き手への行動・呼吸・身体的対処の指示、説教、相談員の助言をしないでください。
自傷、他害、虐待、暴力の具体描写、危険行動、恐怖をあおる展開を入れないでください。
「ぼくだけを頼って」「いつもあなたを見ている」など、排他的な依存や監視を感じさせる表現をしないでください。
実利用者の文章、名前、連絡先、秘密情報、既存作品からの引用を入れないでください。

出力はtitleとstory_textだけを持つJSON object一つです。値は両方とも空でない日本語文字列にしてください。
JSON以外の説明、Markdownの囲み、感情分類JSON、レビュー結果、承認済みという主張、思考過程を出力しないでください。
```

## 置換・失敗の扱い

- 例：`{emotion}`→`寂しい`、`{pet}`→`猫`。両placeholderの残存がないことを確認する。
- 呼出し前に仕様の許可8組を確認する。モデルの「許可外ならエラー」という指示は出力形式を保証しないため、エラー文や不正JSONを物語として採用しない。
- 同じblockをGeminiとローカル候補の両方に使い、実際のprovider・model・parametersをrecordへ残す。無断で表現ルールを弱めない。
- `title` / `story_text`以外のfieldや思考用出力は配布原稿へ混ぜない。人の確認・承認なしで音声化へ進めない。
- このファイルはPromptの仕様であり、自動生成機能や実行scriptではない。
