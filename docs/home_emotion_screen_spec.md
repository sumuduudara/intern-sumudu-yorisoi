## 3. テキスト入力と空入力の扱い

1. 入力カードに複数行で入力する。日本語、改行、句読点を受け付ける。
2. 入力中の内容は画面内で保持する。入力しただけで分析・外部送信を開始しない。
3. 「気持ちを伝える」を押すと、前後の空白を除いた文字列で空入力を判定する。
4. 空文字、半角・全角空白のみ、改行・タブのみは送信しない。
5. 無効な場合は「今の気持ちを入力してください。」を入力欄の近くに表示し、入力欄へフォーカスする。
   空入力でもエラーを案内できるようにボタンを表示するが、分析リクエストは送らない。
6. 有効な場合だけ分析中状態へ移る。処理中の連打でも追加リクエストを作らない。
7. 入力を修正したら古い入力エラーを消し、改めて送信できる。

表示用の元の入力は保持し、分析へ渡す値だけ前後の空白を除く。途中の改行を勝手に削除しない。
文字数上限やAPI固有の制限はIssue本文にないため、検証済みの制限値として作り足さない。
実APIを接続するときに制約を確認し、上限・超過時の案内を追記する。

## 4. 音声入力の仕様

以下は音声認識の基本仕様。**2026-10-22、Issue #8の追加依頼でHomeへのコード接続を行った。**
現在の実装・権限設定・手動確認手順は[`voice_input_spec.md`](voice_input_spec.md)を参照する。ライブ認識は未確認。

- マイクボタンを押した時だけ、対応環境かを確認し、必要なマイク・音声認識の許可を求める。
  画面を開いただけで録音しない。
- 日本語の認識を開始する。認識中であることと停止操作を表示し、同時に複数の認識処理を開始しない。
- 停止・認識完了後の確定テキストを同じ入力欄へ反映し、利用者が確認・修正できるようにする。
  既存の入力があれば、区切りの改行を入れて末尾へ追加し、入力済みの文を無断で消さない。
- 認識しただけでは送信しない。利用者が「気持ちを伝える」を押した後に同じ空入力確認を行う。
- 認識中は分析送信を開始しない。先に停止・確定してから送信する。
- 音声が得られなければ入力を変更せず、「音声を認識できませんでした。もう一度話すか、文字で入力してください。」と案内する。
- 許可拒否：「マイクの利用が許可されていません。文字で入力してください。」。
- 非対応環境・日本語非対応：「この環境では日本語の音声入力を利用できません。文字で入力してください。」。
- 通信失敗等：「音声入力に失敗しました。もう一度お試しください。」。既存のテキストは保持する。
- 停止・画面を離れる操作で録音を終了する。生の録音データを今回の仕様で保存しない。

サービス選定と単体検証の履歴は [`api_service_policy.md`](api_service_policy.md) を参照する。
単体のSTTテスト成功は、Homeへの接続完了を意味しない。
Issue #7作成時のマイクは準備中の案内のみだった。Issue #8では同じ画像・位置のボタンに開始・停止を接続した。
拒否・エラーの実装上の文言はIssue #8仕様を優先し、実端末での成功とコード接続を区別する。

## 5. 状態とボタン動作

| 状態 | 入力・ボタンの扱い | 次の動作 |
| --- | --- | --- |
| 入力待ち・入力中 | テキスト編集、マイク、送信、設定が利用可能 | 送信時に検証する |
| 入力エラー | 入力を保持。エラーを表示 | 修正して再送信する |
| 音声認識中（接続後） | 認識中・停止操作を表示。分析送信と認識の重複開始を抑止 | 停止・確定して入力へ戻る |
| 分析中 | 同じHome内で03-Aの待機表示。編集、再送信、マイク、設定を無効化 | 分析成功・失敗を待つ |
| 分析失敗 | 入力を保持し、日本語エラーと再試行を表示 | 修正または再試行 |
| 分析成功（接続後） | 成功した結果だけを次画面へ渡す | 第7節の配信ルーム一覧へ進む |
| 設定を開く | 入力を画面内で保持 | 設定から戻ると同じ入力を表示 |

画面の破棄後に非同期処理が完了しても画面更新・遷移しない。
キャンセル済みの古いリクエストが完了しても、後から開始した処理を上書きしない。

## 6. 分析とローディング

### 接続後に満たす動作

有効な入力 → 分析中に切り替え → 感情分析サービスを呼ぶ → 成功結果を確認 → 次画面へ移動する。
分析エラー・タイムアウトは失敗として扱い、成功したように見せない。
感情カテゴリ等の結果形式は既存のサービス方針と整合させ、UIプレビューで架空の結果を作らない。

ローディングは独立した分析ページを履歴へ積まず、Home内の状態として表示する。
03-Aの元の背景・ペット・足跡と「気持ちを確認しています...」、英語の補足、手書きメモを参照する。
03-AはHomeと別に確認したデザインであり、Home CSSの流用だけで一致を主張しない。

### 現在の保存済みプレビューの動作

通常のHomeでは、有効な送信後に**ローカルで3秒待つだけ**である。
待機表示に「UIプレビュー：AI分析・おすすめ画面は未接続です。」を表示する。
その後、「感情分析・おすすめ画面はまだ接続されていません。入力内容は送信していません。」と案内する。
「入力に戻る」で内容を保持したまま戻れる。待機中もプレビューを取り消せる。

`lib/home_preview.dart` はFirebaseを初期化しない視覚確認用の入口。
03-Aは「入力に戻る」を押すまで保持する。これは時間がかかっている実AI分析ではない。
本番の入口 `lib/main.dart` と既存の認証確認は維持する。

## 7. 次画面への遷移（Issue #7の要求）

**Issue #7の仕様上、実分析に成功した後の遷移先は「配信ルーム一覧」とする。**
今回の仕様で、この行き先を「Homeへ戻る」や「プレビュー完了ダイアログ」に置き換えない。

1. 成功した分析結果を受け取った場合だけ、配信ルーム一覧へ一度だけ遷移する。
2. 次画面には感情カテゴリ等、推薦に必要な分析結果を渡す。生の入力文をURLやログへ含めない。
3. ルーム一覧からHomeへ戻ると、アプリ内で保持した入力を確認・修正できる。
4. 空入力、認識失敗、分析失敗、キャンセルでは次画面へ進まない。
5. 画面クラス・route名・結果型の具体的な接続は、ルーム一覧・分析サービス側の実装時に決める。
   今回存在しないクラスやAPIを、すでにあるように記述しない。

**既存の全体仕様との相違：** `app_spec.md` はMVPの配信ルーム一覧を対象外とし、
ペットを自動選択してPet Radioへ進むとしている。今回はIssue #7を根拠に上記の遷移仕様を明記する。
全体仕様は無断変更しない。実接続の前にメンターへこの相違を提示し、どちらへ統一するか確認する。
仕様の不一致を隠して、ルーム一覧や自動選択を実装済みとは扱わない。

現在のプレビューは完了案内に留まり、実分析成功・ルーム一覧への遷移を再現していない。

## 8. 設定・認証・エラーと再試行

設定ボタンは設定への入口。設定画面のニックネーム、音量、自動再生等の全機能は今回の仕様作成の範囲外。
現在の保存済みUIは「設定プレビュー」「設定画面全体は準備中です。」と案内するシートを開く。
通常のHomeでは、既存のログアウトをこのシートから呼べる。

- ログアウト成功：既存のFirebase signOut完了後、Welcomeへ移動し、それ以前の画面履歴を消す。
- ログアウト中：二重操作を受け付けず、「ログアウト中...」を表示する。
- ログアウト失敗：Homeに留まり、「ログアウトできませんでした。もう一度お試しください。」と案内する。
- Firebaseを使わない視覚プレビューではログアウトを呼ばず、その制限を表示する。
- 登録、ログイン、保存セッション、パスワード再設定のサービス実装・設定値は変更しない。

| エラー（接続後の仕様） | 表示・回復 |
| --- | --- |
| 空入力 | 「今の気持ちを入力してください。」。入力へフォーカスし、送信しない |
| 分析時の通信失敗 | 「通信に失敗しました。接続を確認して、もう一度お試しください。」。内容を保持 |
| 分析タイムアウト | 「処理に時間がかかっています。もう一度お試しください。」。再試行可能 |
| 無効な分析結果・その他の分析失敗 | 「気持ちを確認できませんでした。もう一度お試しください。」。次画面に進まない |
| 音声の失敗・非対応・許可拒否 | 第4節の案内。テキスト入力へ戻れる |

再試行は現在の入力を再検証し、処理中の重複送信を抑止する。自動で無制限に再送しない。
タイムアウトの秒数、再送回数、API固有のエラーコードは実接続時に確定する。
現在のプレビュー用処理が失敗した場合の実表示は
「プレビューの表示に失敗しました。もう一度お試しください。」と「再試行」であり、
これを実AIの通信障害を検証した証拠にしない。

入力した気持ち、認証トークン、Firebase設定値、内部の例外文をログやエラー文へ出さない。
プレビューは入力を外部送信・永続保存しない。画面を離れた入力の永続復元は今回実装していない。
